# Owner decisions

Status: **Agreed** (2026-11-12). The owner delegated these decisions to the agent in the project-setup session ("decide which is best/appropriate"). The agent chose; the owner can reverse any of them by editing this file and the files it names. Items marked **OPEN** could not responsibly be decided by an agent and still need the owner or legal advice.

## Process and tooling

| # | Decision | Why | Revisit when |
|---|---|---|---|
| D1 | **Impeccable's hook stays OFF for now.** Enable it (`INSTALL-FOR-AGENTS.md` section 4) when the first UI ticket starts. | No UI code exists. The hook runs a downloaded, unaudited engine binary after every edit, including doc edits, outside model approval: all risk, no benefit yet. The skill itself is installed and usable on demand. | First UI ticket (phase C) |
| D2 | **Agent rules marked Agreed:** a limit of 2 sub-agents running at once; test-first only for pure logic; local tracker in `.scratch/`; protected files enforced by CODEOWNERS plus a CI check (once a remote exists); the Tier 1 pre-pilot security check is **done** before any real tester. **Ponytail: keep, provisionally.** | These are the pack's recommendations and fit a small, agent-heavy team. Ponytail's value rests on its author's own benchmark, so it is kept but judged on our evidence. | Ponytail: at the first `retro` after phase D |
| D3 | **`tests/security/**` is a protected file set** (`CODING_STANDARDS.md` section 7). | An agent that can edit the security tests can make them pass. Adding new test files in an explicitly authorised task is allowed; weakening existing ones never is. | — |
| D4 | **Content text is plain text.** `tools/validate-content.mjs` rejects HTML-like tags, `javascript:` URLs, control characters and bidi override characters in any text field (code `markup`). LRM/RLM marks and a bare `<` before a space or digit are allowed. | Transcripts, labels and prompts never need markup. Rejecting it at import is defence in depth; escaping at render time (CS 2.5) is still required. | If a real item needs formatting (use a structured field, not HTML) |
| D16 | **Code host and CI: GitHub (private repository) and GitHub Actions.** The owner creates the repository and pushes; agents never push. CODEOWNERS needs the owner's GitHub username. | Every installed skill comes from GitHub already, and Actions has mature, pinnable security scanners. A stack ADR may confirm or change this. | Stack ADR |

## Product, security and privacy

| # | Decision | Why |
|---|---|---|
| D5 | **Guest mode: yes.** A server-issued guest session (role `guest`) with no personal data. It practises on its own data under the same rules as a learner and can upgrade to an account, keeping its data. With no session at all, everything is denied except starting a guest session, signing up, signing in and password reset. | The blueprint introduces accounts "later, after demonstrating value"; `pre-launch-review.md` Tier 1 says to use anonymous sessions if accounts are not needed. This means less personal data and fewer moving parts. |
| D6 | **Exam review timing:** answer data (answers, authored route, transcript, explanations) is never sent while an exam simulation or independent check is in progress. Review opens once the attempt is submitted. `CODING_STANDARDS.md` 2.2 is reworded to say this. | The blueprint: "Exam simulation: no coaching while testing; review at the end." |
| D7 | **Admin has no access** to learners' or guests' attempts, progress or reports content beyond staff roles. Support requests go through the learner's own export or deletion. | Data minimisation (CS 2.6). A support view would need a new, logged endpoint and a fresh decision. |
| D8 | **Roles:** `content_author` drafts and imports; only `content_reviewer` publishes. One person may hold both roles; an AI never publishes. Staff practise as learners on their own data. | CS 3.1 ("only a human sets published"), workable for a team of one or two. |
| D9 | **One listen in exam mode:** each exam attempt gets one audio grant. The server streams the audio once, forward only: Range requests may resume from the furthest byte already delivered (a dropped connection), never rewind. The grant ends when the audio ends plus a 10 s buffer, or when the attempt is submitted. | Enforceable and testable on the server (EXAM-04). A learner can still record audio on their own device; no server can prevent that, so it is an accepted risk. |
| D10 | **Attempts:** at most one open attempt per user per item, in any mode. An exam attempt on an item the user has already seen (any submitted attempt) is allowed but flagged `seenBefore` and does not count toward independent readiness. | Blocks the "open a guided attempt to read the review, then answer the exam" loophole (EXAM-06/07). Matches the glossary: an independent check uses an unseen task. |
| D11 | **Retention (proposed values, legal review still required before public launch):** guest data deleted after 30 days of inactivity; account data kept while active and deleted after 24 months of inactivity; deletion on request is immediate in the app and gone from backups within 35 days; logs contain no learner personal data and are kept 30 days; pilot research notes are anonymised. | Short, explicit and testable (PRIV-02, PRIV-03). Numbers are conservative defaults, not legal advice. |
| D12 | **Pilot participants are adults (18+)**, confirmed when they are invited. | The selective pilot is invitation-only, so this is easy to enforce and avoids child-data obligations during the prototype. |
| D12b | **OPEN: age policy and parental consent for the public version.** Obligations differ by country (target countries are not fixed). | Needs legal advice; an agent must not decide it. |
| D13 | **Data residency:** no special requirement for the prototype; host in one region, chosen in the stack ADR. **OPEN** for the public version (legal review). | No legal basis yet to choose a region requirement. |
| D14 | **Accounts are optional in the prototype** (guest mode covers it); an account only keeps progress across devices. | Same as D5. |
| D15 | **Threat model updated** for these decisions. It still needs a qualified human review before public launch (`pre-launch-review.md` Tier 2); this record does not replace that. | An agent's review is an aid, not a sign-off. |
