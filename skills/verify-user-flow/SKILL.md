# Verify a user flow

"It compiles", a screenshot, or "the component renders" is **not** verification. Drive the real app, perform the real actions, observe the real result. A control that renders but does nothing is a failure.

If a project verification skill exists (`verify-ielts-app`, generated by `create-verification-skill`), use its Launch/Doctor/Drive/Evidence/Cleanup recipe. If it does not exist yet and the app runs locally, say so and generate it once after this verification rather than improvising a different harness each time. Prefer the repo's own Playwright specs; write a new spec for any flow that lacks one.

## Matrix (run every row that applies to the change; mark the rest N/A with a reason)

| # | Check | How |
|---|---|---|
| 1 | **Happy path end to end** | Start from a fresh state; complete the feature as a learner would; assert the visible outcome AND the stored state (reload and re-read it) |
| 2 | **Every control works** | Click/tap every button and link the feature adds or touches; assert the destination, state change, or content. Dead or fake-data controls are FAIL |
| 3 | **Mode rules** | In exam/independent mode try every forbidden action (replay, hint, skip back, transcript peek) through the UI **and** directly against the API; assert it is refused |
| 4 | **Persistence** | Complete, reload, close and reopen: progress, attempt, and settings survive; another user cannot see them |
| 5 | **Failure states** | Missing/slow/failed audio, offline mid-attempt, expired session, empty data, double-submit: each shows a usable message and a way to recover; nothing is lost silently |
| 6 | **Mobile** | 390x844 touch viewport: no pinch-zoom needed to place an answer on the map, targets >= 44px, nothing clipped, no horizontal scroll |
| 7 | **Desktop** | 1440x900: map and questions visible together |
| 8 | **Arabic / RTL** | Render with `lang="ar" dir="rtl"`: layout mirrors, directional icons flip, mixed English/Arabic text does not scramble, numerals follow the locale setting. English practice content stays LTR inside RTL UI |
| 9 | **Keyboard only** | Complete the flow without a pointer; focus visible and ordered; no traps; map answers reachable by keyboard |
| 10 | **Reduced motion** | With `prefers-reduced-motion`, Answer Replay still conveys the route without animation |
| 11 | **Accessibility scan** | Run the automated a11y scan (axe) on each screen state; record violations. This does NOT replace 9, and screen-reader review is manual |
| 12 | **Replay correctness** | Answer Replay's route matches the authored route and the transcript highlights match the audio at 3 spot-check points |

## Evidence

Save under `docs/testing/evidence/<feature>/<date>/`: the spec run output, screenshots of key states at both viewports, and for failures the exact reproduction steps. Pointers, not prose.

## Report

```
Feature: <id>   Build/commit: <sha>   Env: <local/staging>
1 PASS | 2 FAIL (<repro>) | 3 PASS | ... | 12 NOT VERIFIED (no audio in env)
NOT VERIFIED: <each, with why>
Verdict: VERIFIED | FAILED | PARTIAL (<what remains>)
```

Never write VERIFIED if any applicable row is FAIL or NOT VERIFIED without saying so in the verdict. If a check fails, suspect your observation method before the app (stale server, wrong build, cached asset), then report.
